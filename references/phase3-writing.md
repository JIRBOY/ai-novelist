# Phase 3：分章流水线写作

## 写作模式选择

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **逐章串行** | 主 Agent 逐章写，稳定可靠 | 默认推荐 |
| **子 Agent 并行** | 多个子 Agent 分批并行写 | 追求速度 |
| **Agent Teams** | 多 Agent 协作模式 | 大型长篇 |

## 单章创作流水线

每章严格执行以下步骤：

### Step 1：写前分析

**读取文件（最多 4 个）**：
1. `00_memory/novel_plan.md` — 获取当前章节规划
2. `00_memory/novel_state.md` — 获取当前动态状态
3. `00_memory/foreshadowing_ledger.json` — 检查待回收伏笔
4. `00_memory/retrieval/next_plot_context.md` — RAG 检索推荐上下文（如有）

**生成章节控制卡**（`05_control/chapter_XX_control.md`）：

```markdown
# 第{N}章 控制卡

## 章节定位
- 所属卷：{volume}
- 节奏档位：{慢档/中档/快档}
- 大纲锚点进度：{current}/{total}（{percentage}%）

## 本章必须完成
- 核心事件：{从大纲获取}
- 推进的线：{主线/支线/暗线}
- 回收的伏笔：{如有}
- 新埋伏笔：{如有}

## 本章约束
- 配额检查：A={触发/未触发} B={触发/未触发} C={触发/未触发}（至多1项）
- 事件冷却：{最近使用的事件类型及冷却状态}
- 章末悬念：{必须留下的钩子类型和内容}

## 场景拆分
- 场景1：{地点} — {主角目标} — {障碍} — {悬念}
- 场景2：{地点} — {主角目标} — {障碍} — {悬念}
- 场景3：{地点} — {主角目标} — {障碍} — {悬念}

## 角色状态检查
- {角色A}：当前位置={location}，情绪={mood}，已知信息={known_facts}
- {角色B}：当前位置={location}，情绪={mood}，已知信息={known_facts}
```

### Step 2：Beat Sheet 生成

将章节拆解为 3-5 个 Beat（场景节拍）：

```
Beat 1: {场景标题} — {目标} — {冲突} — {情绪转折}
Beat 2: {场景标题} — {目标} — {冲突} — {情绪转折}
Beat 3: {场景标题} — {目标} — {冲突} — {情绪转折}
Beat 4: {场景标题} — {目标} — {冲突} — {情绪转折}（章末钩子）
```

每个 Beat 限制 800-1200 字，强制限制单次生成的剧情跨度。

### Step 3：Beat 扩写

逐个 Beat 扩写为完整场景：

- 展示而非讲述：用动作和对话表现
- 感官描写：视觉、听觉、触觉、嗅觉（至少 2 种）
- 角色声音：对话符合角色性格 DNA
- 冲突升级：每个 Beat 内有微型冲突
- 信息控制：角色只知道他们应该知道的

### Step 4：章节合成

将所有 Beat 串联为完整章节：
- Beat 间过渡自然
- 时间线连贯
- 情绪弧线完整
- 章末悬念钩子到位

### Step 5：润色去AI味

执行去 AI 味第一遍（详见 `anti-ai-guide.md`）：
- 清除 AI 高频词汇
- 替换抽象套话为具体细节
- 消除模板化过渡
- 恢复角色独特声音

### Step 6：字数检查

- 目标范围：{min_words} - {max_words}
- 不达标则自动扩写或精简
- 记录实际字数到控制卡

## 续写前引导机制

每次执行 `继续写` 时：

1. **引导提问**：询问本章剧情走向偏好
2. **脑洞拓展**：基于大纲和知识库，提供 2-3 个可能的剧情走向
3. **用户确认**：用户选择方向或提供自己的想法
4. **兜底机制**：用户回复"不确定"/"随便"/"自动" → 按大纲自动推进
5. **全自动模式**：开书确认卡选择"全自动" → 跳过引导直接写作
6. **节奏预检**（BLOCKING）：
   - 本章节奏档位及依据
   - 近 3 章配额触发记录
   - 章末保留的具体悬念

## 自动模式（疯狂创作）

用户确认大纲后，可开启连续创作模式：

- 不在每章后反复请求人工确认
- 持续执行：读取文档 → 生成控制卡 → 起草正文 → 逻辑校验 → 更新状态 → 写入日志 → 下一章
- 直到按大纲自然完结

**中断续写**：自动检测未完成项目，从断点继续。检测 `novel_state.md` 中最后完成章节，跳过已完成章节，从下一章继续。

## 并行写作协调（子 Agent 模式）

将章节分成批次，派生子 Agent 并行写作：
- 每批 3-5 章
- 子 Agent 间通过 `00_memory/writing-plan.json` 协调状态
- 批次间有序串行（前批完成才能开始后批）
- 每个子 Agent 完成后回写状态

## 输出格式

```
✅ 第1章完成（3247字）— 悬念：{钩子简述}
✅ 第2章完成（3582字）— 悬念：{钩子简述}
✅ 第3章完成（3412字）— 悬念：{钩子简述}
...
```

正文文件命名：`03_manuscript/第{NN}章-{标题}.md`（两位数补零）

## 异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| 用户在写作中途要求改剧情方向 | 暂停当前章节 → 评估是否需要改纲（如影响主线则走改纲流程）→ 局部调整则修改控制卡后继续 |
| 字数严重不达标（< min 的 50%） | 扩写 Beat 增加场景，而非拉长句子 |
| 字数严重超标（> max 的 150%） | 精简 Beat，合并冗余场景，删减非核心描写 |
| RAG 检索失败/无结果 | 降级为直接读取最近 2 章正文 |
| 续写时发现前文逻辑错误 | 标记为"前文待修" → 当前章节绕过错误继续 → 门禁阶段统一处理 |
| 用户长时间未回复引导提问 | 30 秒后按大纲自动推进（非全自动模式下降级为提供 2-3 个选项） |

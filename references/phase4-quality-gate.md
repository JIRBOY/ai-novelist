# Phase 4：质量门禁

## 六步强制闭环

每章生成后固定执行，按顺序逐项勾选，任何一项未通过都禁止进入下一章：

```
更新记忆 → 一致性检查 → 风格校准 → 去AI味校稿 → 节奏审查 → 门禁检查
```

### Step 1：更新记忆

同步本章变化到状态追踪器：

- 更新 `character_states.json`：角色位置、情绪、能力、已知信息
- 更新 `foreshadowing_ledger.json`：新埋设伏笔、回收伏笔
- 更新 `timeline.json`：本章时间线事件
- 更新 `story_graph.json`：新增节点和边
- 更新 `novel_state.md`：当前章节进度

**产物**：`04_editing/gate_artifacts/chapter_XX/memory_update.md`

### Step 2：一致性检查

检查以下维度的一致性：

| 维度 | 检查内容 |
|------|----------|
| 角色一致性 | 性格、说话方式、行为模式是否与前文一致 |
| 世界观一致性 | 是否违反世界规则、力量体系限制 |
| 时间线一致性 | 事件时间顺序是否合理，有无时间矛盾 |
| 空间一致性 | 角色位置是否合理，移动是否可行 |
| 信息一致性 | 角色已知信息是否正确，有无信息泄露 |
| 伏笔一致性 | 伏笔状态是否正确更新 |

**检查方法**：
1. 读取 `story_graph.json` 和 `character_states.json`
2. 逐条比对本章内容与历史状态
3. 标记所有冲突点

**产物**：`04_editing/gate_artifacts/chapter_XX/consistency_check.md`

```markdown
# 一致性检查报告 — 第{N}章

## 检查结果
- 总体状态：{通过/有条件通过/失败}
- 冲突数量：{count}

## 冲突详情
| # | 维度 | 冲突描述 | 严重程度 | 修复建议 |
|---|------|----------|----------|----------|
| 1 | 角色一致性 | {描述} | {高/中/低} | {建议} |

## 结论
一致性检查: {通过/失败}
失败原因: {若失败}
```

### Step 3：风格校准

检测文风偏移：

- **题材基调**：是否符合题材设定的基调
- **句长节奏**：句长分布是否偏离基线
- **对话比例**：对话与叙述的比例是否合理
- **感官密度**：感官描写密度是否达标
- **AI 词汇频率**：AI 高频词出现频率

**产物**：`04_editing/gate_artifacts/chapter_XX/style_calibration.md`

### Step 4：去AI味校稿

**两遍式润色**（详见 `anti-ai-guide.md`）：

#### 第一遍：清除 AI 模式

逐段扫描，针对 7 类 AI 写作模式逐一处理：

1. AI 高频词汇（不禁、仿佛、映入眼帘、心中暗道…）
2. 弱化副词（似乎、好像、大概、或许…）
3. 意义膨胀（在某种程度上、从某种意义上说…）
4. 通用套话（在这个关键时刻、一时间…）
5. 论文结构（首先、其次、综上所述…）
6. 正式语体（对...进行了...、值得注意的是…）
7. 排比三连（三段式排比、对仗工整…）

**原则**：最小化改动，只改有问题的地方，不破坏原有叙事。

#### 第二遍：AI 自审

完成第一遍后，对修改稿提问：
> "这段文字哪些地方还是明显 AI 生成的感觉？"

列出 3-5 条具体问题，再次修改后输出最终版。

**产物**：`04_editing/gate_artifacts/chapter_XX/humanizer_pass.md`

### Step 5：节奏审查

读取章节正文，完成档位判断、A/B/C 配额核查、章末悬念质量评估、隐性加速检测四项判断（详见下方"节奏审查执行规范"）。

**产物**：`04_editing/gate_artifacts/chapter_XX/pacing_review.md`

### Step 6：门禁检查

脚本化校验发布标准，生成最终判定：

```json
{
  "chapter": "第{N}章",
  "checks": {
    "word_count": { "passed": true, "actual": 3247, "min": 3000, "max": 5000 },
    "consistency": { "passed": true, "conflicts": 0 },
    "style": { "passed": true, "deviation": "low" },
    "humanizer": { "passed": true, "ai_patterns_remaining": 2 },
    "pacing": { "passed": true, "tier": "中档", "quota_violation": false },
    "suspense_hook": { "passed": true, "level": "强", "type": "危机型" }
  },
  "passed": true,
  "timestamp": "{ISO 8601}"
}
```

**产物**：`04_editing/gate_artifacts/chapter_XX/gate_result.json`

**门禁通过条件**：所有 checks 均 `passed: true`

## 门禁失败处理

当 `gate_result.json` 显示 `passed: false` 时：

1. **识别失败项**：读取 gate_result.json 中 `passed: false` 的检查项
2. **生成修复路径**：针对每个失败项生成最短修复方案
3. **执行修复**：按修复方案修改章节正文
4. **重新门禁**：修复后重新执行六步闭环
5. **防死循环**：单章最多 3 轮修复，超过则强制暂停请求人工介入

```
❌ 第{N}章门禁失败
   失败项：{check_name} — {reason}
   修复方案：{fix_description}
   正在执行修复（第{attempt}轮/最多3轮）...
```

## 节奏审查执行规范（Step 5 详细）

执行节奏审查时，读取章节正文并完成以下四项判断：

### 一、档位判断

- **慢档**：铺垫/羁绊/风土人情，主线零推进，每 3-4 章至少 1 章
- **中档**：次要矛盾升温未爆发，占比 ≥60%
- **快档**：主线突破，每卷 ≤2-3 次，快档后必须有慢/中档缓冲

### 二、A/B/C 配额核查

- A（主线矛盾实质推进）：本章主线格局是否发生实质性、不可逆的改变
- B（主要关系决定性升级）：主要角色关系是否到达决定性节点
- C（核心秘密完整揭露）：核心秘密是否在本章被完整揭露
- **违规条件**：同时触发 ≥2 项

### 三、章末悬念质量

- **强**：读者必须看下一章才能得知关键信息
- **中**：有悬念但可推测
- **弱**：悬念模糊或可有可无
- **无**：无悬念（非慢档收尾时为失败）

### 四、隐性加速检测

检查是否存在关键词未覆盖的隐性加速（如：看似日常但实际推进了主线核心矛盾）。

**产物**：`04_editing/gate_artifacts/chapter_XX/pacing_review.md`
